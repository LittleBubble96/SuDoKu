| 字段 | 用途 |
| --- | --- |
| id | 唯一奖杯 ID，发布后不要更改，否则会成为新的收藏项 |
| year / month | 所属年月；年份从 2026 起，月份 1–12；一个年月只配置一个奖杯 |
| iconObtained / iconNotObtained | 已获得与未获得的资源名，不带扩展名 |
| nameKey / descriptionKey | 名称和解锁说明的多语言 Key |
| unlockType | `AllDailyChallengesInMonth`：整月；`DailyChallengeCountInMonth`：当月指定天数 |
| unlockValue | 整月填 0，由程序计算当月实际天数；指定天数填 1–当月天数 |
| sortOrder | 年内排序 |

新增年份时，在表中新增十二行并使用新的唯一 ID。修改解锁条件时同步选择相符的说明 Key。解锁类型不支持时配置校验会报错，不会自动当成其他条件。

## 管理器与存档

入口：`SudokuPresenter.Current.Trophies`，类型为 `SudokuTrophyManager`。启动时异步加载 `TbTrophy`，然后注入 `SudokuGameController`。管理器不加载图标、不翻译文字、不创建 UI。

```csharp
var trophies = SudokuPresenter.Current.Trophies;
var years = trophies.Years;                      // 配置中存在的年份，升序
var items = trophies.GetForYear(2026);           // 按配置排序
var august = trophies.GetForMonth(2026, 8);      // 未配置返回 null
var trophy = trophies.Get(202608);              // 未配置返回 null
int collected = trophies.CollectedCount(2026); // 年度已获得数量
```

每个 `SudokuTrophyProgress` 提供 `Config`、`CompletedDays`、`RequiredDays`、`State`、`IsObtained`、`AwardedDate` 和当前 `Icon` 资源名。后续 UI 可以读取 `Config.NameKey` / `DescriptionKey` 交给项目本地化模块。年度总数取 `items.Count`。

- `NotObtained`：过去月份尚未获得，仍可通过补玩解锁。
- `InProgress`：当前月份尚未获得，进度显示完成天数 / 条件天数。
- `NotStarted`：未来月份，未开放。
- `Obtained`：已获得，优先于日期状态，使用彩色图标。

默认规则是完成所属月全部每日挑战，自动获得，无需另点领取。按日期去重统计，仅统计已完成且不晚于当前日期的有效记录；普通模式通关、部分进度、重复日期不累计。2 月 28 / 29 天以及大小月按实际年份计算。补玩往月的最后一日同样可以自动解锁。

在 `GameCacheData` 新增可选 `trophyAwards` 列表，保存 `id` 和 `awardedDate`（实际获得日期）。缓存版本继续为 1，兼容旧存档；已有完整月份在启动时补记奖杯。已获得记录不会因历史每日记录丢失或配置条件提高而取消。保留暂时未配置的旧 ID，但年度收集数只计当前配置项。

控制器保存每日进度时同时判定奖杯并写入同一缓存。新增获得后发送 `EventDefine.SudokuTrophiesChanged`（无参数），重复保存不重复发送。GM 重置进度会同步清空奖杯。
