## 3. 必须沿用的开发方式

- 阅读工程 `CLAUDE.md`。本会话已参考过 TEngine 的 UI 生命周期、资源、事件、热更和配置表规范；实际源码 API 优先于旧文档示例。

- 如异步初始化与现有生命周期确实冲突，应先向用户说明冲突和具体处理方案；此前已确认“等待棋盘就绪后再允许操作”的时序，不需重复询问。
- 访问模块用 `GameModule.XXX`。事件随窗口生命周期管理，防止重复订阅、关闭后旧回调和重复生成。
- 代码必须在当前项目内；不再保留项目外的 Demo 实现。
- 布局、适配和图标由用户搭建，不擅自替换。缺少弹窗时只留现有入口，不用代码临时拼一套 UI。
- 不使用 `SudokuUIAuthoring` 一类自动生成工具，不新建 SDF 字体。缺字补语言表，再使用既有导表／字体生成流程。
- GM 继续使用现有 TMP 方案。用户曾说用旧 Text，随后撤回；不要恢复那条已经撤回的要求。
- 新增非 GM 文案补中英文；GM 专用文案不要求英文。

## 5. 当前启动与页面跳转

实际流程为：

`GameApp → SudokuPresenter.LaunchAsync → 并行加载六档题包 → 加载缓存 → 创建控制器／主题 → UIHome → 等待首页内容就绪 → 非发布版初始化 GM`。

部分旧 README 仍写“直接打开 UISudoku”，该说法已过期，以 Presenter 源码为准。

跳转接口：

- `SudokuPresenter.ShowHomeAsync()`：返回首页，保留当前对局并停止计时。
- `SudokuPresenter.ContinueGameAsync()`：继续已有对局，恢复用时；此前暂停时会解除暂停。
- `SudokuPresenter.StartNewGameAsync(difficulty)`：选定档位开始第一道未完成题。

跳转使用 `IsNavigating` 和 `UIInteractionLock` 防止重复操作。新游戏会先等待窗口和棋盘加载成功，再替换旧局，避免资源加载失败就丢掉旧题。

| 参数 | 值 | 用途 |
| --- | --- | --- |
| CompletionFadeIn | 0.06 秒 | 单格亮起 |
| CompletionFadeOut | 0.12 秒 | 单格恢复 |
| CompletionStepDelay | **0.05 秒** | 向外传递间隔，用户已调快 |

## 9. 题库与生成算法

当前目录：`Assets/AssetRaw/Configs/Sudoku/`。

| 难度 | 文件 | 题数 | 字节 |
| --- | --- | ---: | ---: |
| 快速 | sudoku_quick.bytes | 20 | 836 |
| 初级 | sudoku_beginner.bytes | 20 | 836 |
| 中级 | sudoku_intermediate.bytes | 20 | 836 |
| 高级 | sudoku_advanced.bytes | 20 | 836 |
| 专家 | sudoku_expert.bytes | 20 | 836 |
| 大师 | sudoku_master.bytes | 20 | 836 |
| 合计 | 六个包 | **120** | **5,016** |

格式：16 字节文件头＋每题 41 字节。两个格子打包到一个 byte，高四位在前，81 格最后多出的低四位补 0。0 表示空格。头部含 SDKP 标识、版本、难度、记录大小、数量和 CRC32。

只保存题面，不保存答案。进入题目／恢复时求解并验证唯一解。解锁进度中的题号是内部索引，不是面向玩家的关卡编号。

生成在开发阶段离线执行，不在小游戏启动时反复随机生成。生成终盘、挖空并保留唯一解后，通过人类技巧求解器评级；不满足目标难度的题目舍弃后继续生成，收满后输出题包。

现有评级范围：

- 快速：单格唯一候选，保留较多已知数。
- 初级：增加行／列／宫唯一位置。
- 中级：交叉排除、显性数对。
- 高级：隐性数对、显性／隐性三数组。
- 专家：X-Wing、XY-Wing。
- 大师：Swordfish、单数字强链双色排除。

中级以上需要低一档解不完而本档可以解完。技巧库解不完的题不自动算大师。扩库后 CRC 改变，旧索引与填写状态可能不能继续套用，需考虑现有存档兼容逻辑。
