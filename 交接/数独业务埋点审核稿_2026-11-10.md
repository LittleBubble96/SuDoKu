# 数独业务埋点审核稿

审核日期为 2026-11-10。本稿覆盖对局、奖励、广告、游戏说明和首页入口。启动和登录继续使用现有的 sdk_login、startup_step、startup_complete 与微信原生游戏启动上报。业务事件统一走 GameSDK.SDK.ReportEvent。具体事件名和字段以本稿两张表为准。

## 待确认的广告规则

- **Banner 门槛 N 和激励视频门槛 M**。建议分别配置，两个门槛各自判断。累计普通关卡通关数达到对应门槛即解锁。从所有难度累计，同一难度下同一道题只计首次通关，每日挑战、重复通关和 GM 调试成绩排除。建议纳入旧存档中可确认的普通通关进度。N、M 的具体数值待定。
- **Banner 展示条件**。达到 N 后，棋盘就绪、小游戏在前台、局内可操作时才展示。建议普通局和每日挑战均可展示。离开对局、切后台、暂停、弹出说明或设置、展示激励视频、通关结算时隐藏。满足条件后再次成功显示时，记为新的一次展示。
- **Banner 时长建议采用「满 30 分钟分段上报，隐藏时补报余量」**。30 分钟即 1,800,000 毫秒，是单次连续展示内的上报周期。由显示成功开始计时，用单调时钟累计实际可见时间。隐藏、切后台、离开棋盘、通关、销毁或广告异常时结束本次展示并报剩余时长。剩余为 0 时省略尾包。短局同样能上报。分段只传本次新增时长，汇总时按展示 ID 和分段序号去重后相加。
- **Banner 示例**。连续可见 37 分钟时，第 30 分钟发 1,800,000 毫秒，隐藏时发剩余 420,000 毫秒。展示 2 分钟就退出棋盘时，退出时发 120,000 毫秒。切后台 5 分钟再回来，后台的 5 分钟不计入展示时长。
- **激励视频展示条件**。达到 M 后，允许玩家在支持的入口主动触发，入口包括提示、签到、每日奖励和结算。展示成功时记展示事件，观看结束或播放失败时记结果，奖励实际到账时另记领奖。内部重试沿用同一个请求 ID，同一请求最多计一次展示和一次结果。

## 表一 · 参数字典

类型是业务定义。现有 SDK 参数容器使用字符串，整数用十进制，布尔统一传 1 或 0，日期用游戏本地日期。字段在事件表中出现时才传。失败原因使用有限枚举，关卡、广告和奖励只传业务标识及汇总数据。

| 参数键 | 类型及格式 | 含义与取值 |
| --- | --- | --- |
| round_id | 字符串 | 本次对局唯一 ID。新开或重开生成，恢复沿用存档 ID。旧存档首次恢复时补 ID。 |
| mode | 枚举 | normal 普通局，daily 每日挑战。 |
| difficulty | 整数 0–5 | 快速、初级、中级、高级、专家、大师，使用工程难度枚举。 |
| level_id | 整数，从 1 开始 | 当前难度下的题目编号。普通关卡用 difficulty 与 level_id 组合识别。 |
| challenge_date | 日期 YYYY-MM-DD | 每日挑战对应的题目日期，补做时仍用题目的原日期。仅 daily 事件适用。 |
| start_source | 枚举 | new_game 新游戏，daily_challenge 每日挑战新开，restart 重开，next_round 结算后下一局。 |
| duration_ms | 非负整数，毫秒 | 对局累计有效游玩时长，继续事件用进入时已有时长。 |
| progress_pct | 整数 0–100 | 以题目空格中已填正确的格数计算，通关为 100。 |
| score | 非负整数 | 本次结算分。 |
| mistake_count | 非负整数 | 本局累计填错次数，撤销不回退。 |
| hint_count | 非负整数 | 本局成功使用提示次数。 |
| perfect | 布尔 0 或 1 | mistake_count 为 0 时为 1。 |
| current_streak | 非负整数 | 此局通关后该难度的当前连胜。 |
| abandon_reason | 枚举 | replaced 被新局替换，restart 重开。 |
| hint_source | 枚举 | inventory 提示库存，coins 金币兑换，rewarded_ad 激励视频。 |
| guide_action | 枚举 | show 成功展示，dismiss 玩家关闭。 |
| guide_source | 枚举 | first_game 首次进局自动展示，settings 设置页手动打开。 |
| entry | 枚举 | game_club 游戏圈，other_games 其他游戏，daily_challenge 每日挑战，sign_in 签到，daily_task 每日任务。 |
| target_game | 字符串 | 目标游戏的稳定业务标识，寻字大师用 xunzi。 |
| navigation_result | 枚举 | success 成功，cancel 用户取消，failed 失败。 |
| navigation_reason | 枚举 | canceled、sdk_error、unknown。仅取消或失败时传。 |
| trophy_id | 正整数 | 奖杯配置 ID。 |
| trophy_month | 年月 YYYY-MM | 奖杯对应的挑战月份。 |
| completed_days | 非负整数，天 | 发放时该月已完成的不同每日挑战天数。 |
| required_days | 正整数，天 | 奖杯配置计算出的当月解锁门槛。 |
| award_date | 日期 YYYY-MM-DD | 奖杯实际发放日期，和奖杯月份可不同。 |
| award_source | 枚举 | challenge_complete 完成挑战后发放，reconcile 读档补发尚未获得的奖杯。 |
| ad_feature | 枚举 | banner 或 rewarded_video。 |
| unlock_threshold | 正整数，关 | 生效的广告门槛，Banner 对应 N，激励视频对应 M。 |
| completed_normal_levels | 非负整数，关 | 按上述口径累计的不同普通关卡首次通关数。 |

## 实现与验收口径

- 对局、奖杯和奖励事件在业务状态成功提交时触发。过滤 GM 调试、已获得奖杯、存档重放与重复领取。延续现有胜负口径，填错或停留过久不会判负。
- Banner 时长统计的起止应接实际显隐和应用前后台状态。SDK 展示成功是本项目的曝光判定依据。若应用被强制终止，结束回调可能无法执行，时长以最近已上报的分段为准。
- 激励视频展示、观看结果、奖励到账分别核对。同一广告即使内部重试，展示和结果仍各至多一次。用户提前关闭时记录结果，奖励到账事件仅在发奖成功时产生。
- 验收覆盖 N−1 与 N、M−1 与 M 两个门槛边界。分别验证普通局、每日挑战、继续旧局、暂停与恢复、切后台、离开棋盘、通关、广告提前关闭和重复领奖。Banner 至少验收一例短于 30 分钟和一例超过 30 分钟的展示。
- 本稿审核时待确认 N、M 的具体数值，以及是否采用本文建议的累计通关口径、Banner 展示范围和 30 分钟分段周期。
